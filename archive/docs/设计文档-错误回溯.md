# 设计文档：错误回溯（QOL-1）

> 问题：所有错误都是裸 `AssertionError("Undefined variable: 'x'")`——**没有调用链、
> 没有源码位置**。定位错误靠人肉追。
> 现状基线：lab/learning `340579c`（TYPE-3 常量折叠已完成；MEM-2 g_call_stack 就绪）

---

## 一、现状：裸 AssertionError 的痛点

```python
# 现在（无上下文）：
AssertionError: Undefined variable: 'x'
```

痛点：
1. **不知道在哪个函数**（main? helper? inner?）
2. **不知道在哪一行**（AST 节点有 `coord` 但没用）
3. **无法区分错误类别**（未定义变量 vs 类型错 vs 指针错——全靠人读消息）
4. **嵌套函数调用时无调用链**（哪个调用点触发的最深错误？）

## 二、设计：异常体系 + 调用链 + 源码位置

### 2.1 自定义异常体系

```python
class InterpreterError(Exception):
    """解释器错误基类。"""
    def __init__(self, message, node=None):
        self.message = message
        self.node = node            # 出错 AST 节点（取 coord 定位）
        super().__init__(message)

class UndefinedVariable(InterpreterError): ...   # 未定义变量/函数
class TypeError_(InterpreterError): ...          # 类型错误（指针/下标/成员）
class UnsupportedError(InterpreterError): ...    # 未支持特性（goto/指定初始化器等）
class LinkError(InterpreterError): ...           # 链接错误（原型无定义）
```

**兼容策略**：`InterpreterError` **继承 `AssertionError`**——现有测试 `except AssertionError` 全部兼容，无需改动。

### 2.2 报错增强（execute() 顶层包装）

在 `execute(node)` 的异常传播路径加"坐标附注"：

```python
def _attach_coord(exc, node):
    """给 InterpreterError 补上首次出错的源码位置。"""
    coord = getattr(node, 'coord', None)
    if coord is not None and not getattr(exc, '_has_coord', False):
        exc._has_coord = True
        exc.message = f"{coord}: {exc.message}"
```

错误消息最终形如：
```
test/foo.c:12:5: 未定义变量 'x'
```

### 2.3 调用链（使用 MEM-2 的 g_call_stack）

`program.run()` 顶层捕获 InterpreterError 时打印调用链：

```
[error] test/foo.c:12:5: 未定义变量 'x'
调用链:
  main() at test/foo.c:10
    → helper() at test/foo.c:7
      → inner() at test/foo.c:4
```

调用链来源：`g_call_stack`（MEM-2 已有，StackFrame.func_name）；
坐标来源：调用点 AST 节点（StackFrame 增 `call_coord`，调用时记录 `self.node.coord`）。

### 2.4 保留控制流异常

`ReturnException`/`BreakException`/`ContinueException` 是**正常控制流**，不参与报错
（保持独立，不继承 InterpreterError）。

## 三、对现有功能的影响

| 现有能力 | 变化 |
|---|---|
| 测试 `except AssertionError` | 兼容（InterpreterError 继承 AssertionError） |
| `str(e)` 消息 | 前缀多了 `coord:`（测试断言含 `'xxx' in str(e)` 仍过；含 `'未定义' in str(e)` 仍过） |
| 控制流（return/break/continue） | 不变 |
| 错误定位 | **新增**：源码位置 + 调用链 |
| 性能 | 仅出错路径有开销（正常路径零影响） |

**风险点**：现有测试若断言 `str(e)` **以特定词开头**（而非 `in`）可能受影响——需
回归时留意；文档记录"消息前缀带 coord"。

## 四、实施步骤

1. `execute.py`：定义 `InterpreterError`（继承 AssertionError）+ 子类 + `_attach_coord`
2. `Scope._get` 等关键 raise 点：裸 `AssertionError` → 子类（未定义变量→UndefinedVariable 等），
   并传 `node`（改 Scope API：`get(name, node=None)`）
3. `execute(node)`：except AssertionError 时不打断（保持原样），但在**顶层传播**时
   由 `run()` 捕获 InterpreterError 附坐标 + 打印调用链
4. `StackFrame` 增 `call_coord`；`ExeFuncCall` 调用时记录 `self.node.coord`
5. `program.run()`：`try/except InterpreterError` → 打印 `[error] <coord>: <msg>` + 调用链
6. 测试：
   - 未定义变量报错含 `coord` + 调用链（多层函数）
   - 指针错误/类型错误分类
   - 现有测试 `except AssertionError` 全兼容
7. 全量回归 + 文档更新

## 五、验收

- ✅ 错误消息带源码位置（`test/foo.c:12:5: 未定义变量 'x'`）
- ✅ 多层调用报错打印完整调用链（main → helper → inner）
- ✅ 错误分类：UndefinedVariable / TypeError_ / LinkError 可区分
- ✅ 现有测试零破坏（InterpreterError 继承 AssertionError）
