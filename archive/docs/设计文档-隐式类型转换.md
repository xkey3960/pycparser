# 设计文档：隐式类型转换（TYPE-2）

> 问题：C 的 Usual Arithmetic Conversions（整型提升 + 二元运算提升 + 赋值/参数
> 转换）未实现——`_TYPE_CONVERTERS` 只是名字→Python 函数，BinaryOp 提升只有
> "浮点→double 否则 int"的宽松处理。
> 现状基线：lab/learning `2a14e2e`（MEM-4 堆管理已完成）

---

## 一、现状与缺失

| C 规则 | 现状 | 缺失 |
|---|---|---|
| 整数提升（char/short → int） | 无 | `char c; c + 1` 按 int 算（碰巧对），但 `sizeof` 类型推导不准 |
| 二元运算提升（Usual Arithmetic Conversions） | 仅"任一浮点→double，否则 int" | `int + unsigned`、`long + int`、`float + double` 等级不对 |
| 赋值转换 | 无（直接存值） | `int x = 3.7;` 应截断为 3；`char c = 200;` 应截断 |
| 函数参数转换 | 无（原样传） | 形参 `double` 实参 `int` 应转 double；`char` 提升 |
| 返回转换 | 无 | `return 3.7;`（函数返 int）应截断 |

## 二、设计：类型等级系统 + 统一转换

### 2.1 类型等级（rank，C 标准 §6.3.1.8）

```python
# 等级从低到高（同等级 signed/unsigned 视为同一"可比较"族）
_RANK = {
    '_Bool': 0, 'bool': 0,
    'char': 1, 'signed char': 1, 'unsigned char': 1,
    'short': 2, 'short int': 2, 'signed short': 2, 'signed short int': 2,
    'unsigned short': 2, 'unsigned short int': 2,
    'int': 3, 'signed': 3, 'signed int': 3, 'unsigned': 3, 'unsigned int': 3,
    'long': 4, 'long int': 4, 'signed long': 4, 'signed long int': 4,
    'unsigned long': 4, 'unsigned long int': 4,
    'long long': 5, 'long long int': 5, 'signed long long': 5, 'signed long long int': 5,
    'unsigned long long': 5, 'unsigned long long int': 5,
    'float': 6, 'double': 7, 'long double': 8,
}
```

### 2.2 Usual Arithmetic Conversions（二元运算）

```
usual_convert(t1, t2)：
  1. 任一是 long double → long double
  2. 任一是 double → double；任一是 float → float
  3. 整型提升（< int 的按 int/unsigned int）
  4. 同等级：有 unsigned → unsigned；否则更高等级
  （完整 C 规则含"等级相同 signed 不敌 unsigned"的细节，解释器简化：
   等级决定；同等级 unsigned 优先）
```

`ExeBinaryOp` 求值后按 `usual_convert(左类型, 右类型)` 转换两个操作数再运算；
`infer_type(BinaryOp)` 返回 `usual_convert` 的结果类型（`sizeof` 等类型上下文准确）。

### 2.3 整型提升（integer promotion）

`promote(t)`：char/short/_Bool（rank < int）→ int（若 int 能表示全部值，否则
unsigned int——解释器简化：直接 int，等价常见 64 位平台）。

### 2.4 赋值/初始化/返回/参数转换

统一入口 `convert_to(value, target_type)`：

| 目标 | 规则 |
|---|---|
| int/unsigned/long/...（整型） | `int(value)` 截断（float 3.7→3）；bool→0/1 |
| float/double | `float(value)`（int→float） |
| char | `int(value) & 0xFF`（截断到 8 位） |
| _Bool | `bool(value)` |
| 指针 | 原样（整数 0 → NULL 语义） |
| struct/union/数组 | 原样（coerce_to_type 已有值语义，不重复） |

接入点：
- `ExeAssignment`（`=`）：`rval = convert_to(rval, 左值类型)`（读 g_scope.get_type）
- `ExeDecl` 初始化：`coerce_to_type` 前对**标量**做 convert_to（struct/数组走现有路径）
- `ExeFuncCall` 参数：`convert_to(实参, 形参类型)`（形参类型已知时）
- `ExeReturn`：`convert_to(返回值, 函数返回类型)`

### 2.5 与既有机制的关系

- `coerce_to_type`（复合类型值语义）保留，TYPE-2 只在其**前**做标量转换
- `_TYPE_CONVERTERS`/`_convert_value`（cast 路径）保留，Cast 是显式转换不走隐式
- `infer_type` 升级 BinaryOp 分支（用 usual_convert），其余分支不变

## 三、对现有功能的影响

| 现有能力 | 变化 |
|---|---|
| 整型运算（int+int） | 不变（等级相同） |
| 浮点参与（int+double） | 更准确（double 转换后运算）——当前已近似 |
| enum（IntType） | 视为 int 参与提升 |
| 赋值 `int x = 3.7` | **新增**：截断为 3（之前存 3.7） |
| `char c = 200` | **新增**：截断为 -56（0xC8 & 0xFF 按有符号解释）——按 int 存 |
| 函数参数（形参 double/实参 int） | **新增**：转 double |
| `sizeof(表达式)` | 更准确（BinaryOp 类型推导按提升规则） |

## 四、实施步骤

1. `execute.py`：新增 `_RANK`、`promote()`、`usual_convert()`、`convert_to()`
2. `ExeBinaryOp`：求值后按 usual_convert 转换两操作数；`infer_type` BinaryOp 用 usual_convert
3. `ExeAssignment`：`=` 赋值前 convert_to（目标 = 左值类型）
4. `ExeDecl`：标量初始化前 convert_to
5. `ExeFuncCall`：实参按形参类型 convert_to；`ExeReturn`：返回值按函数返回类型 convert_to
6. 测试：
   - `char c=200; c+1` → 提升 int；`sizeof(c+1)==4`
   - `int x = 3.7` → 3；`double d = 3` → 3.0
   - `1 + 2.5` → 3.5（float 提升）；`unsigned int u=...; u + (-1)` 语义
   - 形参 double 实参 int → double（`f(3)` 得 3.0）
   - `return 3.7`（int 函数）→ 3
7. 全量回归 + 文档更新

## 五、验收

- ✅ 整数提升：`sizeof(char+1)==4`、`sizeof(short+short)==4`
- ✅ 二元提升：`1+2.5==3.5`、`float+double→double`
- ✅ 赋值转换：`int x=3.7` → 3、`char c=200` 截断
- ✅ 参数/返回转换：实参 int→形参 double、`return 3.7`（int 函数）→ 3
- ✅ 既有测试零回归（int/int、enum、struct 值语义不变）
