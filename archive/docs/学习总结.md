## 四、自定义工作（lab/learning 分支，重点）

### 1. GNU C 扩展解析器 — `pycparserext/`

继承上游 `CParser`，扩展出 GCC/OpenCL 语法支持：

- **AST 扩展节点（11 个）**：`TypeList`、`AttributeSpecifier`（`__attribute__`）、`Asm`（内联汇编）、`PreprocessorLine`、`TypeOfDeclaration` / `TypeOfExpression`（`__typeof__`）、`RangeExpression`（`a...b`）、`TypeDeclExt`、`ArrayDeclExt`、`StructExt`、`FuncDeclExt`
- **解析器类**：`GnuCParser`、`OpenCLCParser`（基于 `CParserBase` + `_AsmAndAttributesMixin`）
- **已支持的扩展语法**：`__attribute__`、`__asm__`、`__typeof__(x)`、**GNU 语句表达式** `({ i; })`、指定初始化器 `.field`/`[index]`、`case 1...5` 区间

### 2. C AST 解释器 — `execute.py`

用 Python 直接"执行" C 代码的 AST，**共覆盖 60 个节点类型 = 49 个标准节点 + 11 个 GNU 扩展节点**。

- **分发机制**：`g_exe_class` 字典（QOL-3 加类键镜像 `_EXE_BY_CLASS`），`execute(node)` 查表分发；Constant/ID 内联（跳过执行器对象）
- **运行时**：`Scope`（父链作用域）、`Function`、`StackFrame` 调用栈（MEM-2）、`Address` 指针模型（MEM-1）、控制流异常体系
- **错误体系（QOL-1）**：`InterpreterError` 继承 AssertionError（测试零破坏），子类 `UndefinedVariable`/`TypeError_`/`MemoryError_`/`UnsupportedError`/`LinkError`；coord 定位 + 调用链快照（QOL-2 把裸 Python 异常也纳入分类）

### 3. 类型系统 — `typesys.py`

- **CType 层次**：Basic/Ptr/Array/Func/Enum/Struct/Union + `TypeRegistry`（内建/标签命名空间/typedef 链，环检测）
- **布局**：`compute_struct_layout`（对齐+padding+位域+灵活数组成员）、`compute_union_layout`
- **类型转换（TYPE-2）**：`_RANK` 等级 + `promote`/`usual_convert`/`convert_to`，赋值/参数/返回统一路径
- **常量折叠（TYPE-3）**：case 表达式/枚举/字符/range + 位域宽度 `_fold_bitsize`
- **惰性类型（L4）**：注册与布局分离，`ensure_complete` 用时补全；`_deferred`/`_dupes` 冲突检测

### 4. 多文件 / 惰性 / 编译管线 — `program.py` + `sources.py`

- **S1-S3**：`CProgram` 链接三阶段（1a 类型 → 1b 函数 → 2 全局）+ 冲突检测 + 入口定位
- **S4**：`static` 文件级作用域（`g_static_funcs`/`g_static_globals`）+ CLI（`python program.py a.c b.c --entry main`）
- **L1-L4**：符号索引 + 惰性装载；L4 = 全局 eager + 类型 lazy；方案 C strict 可达性预链接（只装载可达文件）
- **QOL-4**：多线程并行解析（ThreadPoolExecutor，6 文件 -79%）+ AST 缓存持久化（sha256 文件 hash 命中直接反序列化，跳过 gcc+解析）

### 5. 内置函数与堆 — `cbuiltins.py`

- 注册表（`@builtin` 装饰器三步扩展）+ 50+ 常用函数（printf/string/ctype/math/rand/va_list）
- 堆管理（MEM-4）：first-fit 分配器 + 相邻合并 + malloc 永不返回 0（`_HEAP_BASE=8` 避 NULL）

### 6. 控制流里程碑

- **CTRL-1 Goto**：两遍扫描收集 Label + `GotoException` 跳转（前跳/回跳/跳出循环/嵌套跳外层）
- **CTRL-2 setjmp/longjmp**：`LongJmpException` 跨栈帧 unwind + 调用点重放（setjmp 二次返回 retval）

### 7. 静态分析：持锁调用检查 — `lockcheck.py`（分支 lab/lock-check）

规则：函数 F 不允许在持有**任意锁**的状态下被调用（任何加锁之后、解锁
之前不得调用 F）。纯静态分析，不依赖解释器：

- **解析**：gcc -E（UTF-8 解码 + 每文件重试）+ GnuCParser；规避 Windows
  GBK 环境解码失败与云盘占位文件瞬时空读
- **CFG**：函数 AST → 基本块图；表达式内调用按求值顺序抽事件
  （`if (mutex_lock(&m)==0)` 里的加锁也能识别）
- **函数内 may-数据流**：状态 = 持锁集合，分支并集合并，块级不动点
- **跨函数**：callee 无关摘要（adds 从 entry=∅ 推导，rels 语法计算）
  + IN 单调传播——wrapper（如 lock_ledger 包 mutex_lock）无需配表
  自动覆盖；无振荡
- **函数指针**：间接调用 → 告警不静默（不假装 sound，人工补位）
- 用法：`python lockcheck.py *.c --forbid log_tx,log_event`
- demo：`examples/lockcheck_demo/`（多文件银行转账系统，5 处埋点违规
  + 4 类干净模式 + 函数指针边界），`test_lockcheck.py` 6 组断言全绿，
  违规行号与源码一一对应

## 七、如何使用

```bash
# 解析 C 代码（需要先预处理）
python -c "
from pycparser import parse_file
ast = parse_file('examples/c_files/basic.c', use_cpp=True,
                 cpp_args=r'-Iutils/fake_libc_include')
ast.show()
"

# 运行 C 程序（多文件 + 惰性装载）
python -c "
from program import CProgram
prog = CProgram(['a.c', 'b.c'])   # 默认 lazy + 并行 + AST 缓存
prog.load()
print(prog.run())                  # 打印 main() 返回值
"

# 跑全部测试（本地 + 上游 + LOCK-CHECK）
pytest

# 持锁调用静态分析（LOCK-CHECK）
python lockcheck.py a.c b.c --forbid log_tx,log_event
```

注意：真实 C 代码几乎都必须先经过 C 预处理（`cpp` / `gcc -E`），并用
`utils/fake_libc_include` 假头文件替代真实标准库头。
