# 设计文档：栈帧与递归支持（MEM-2）

> 问题：函数调用目前用 `Scope(func.closure_scope)` 模拟作用域，递归虽可运行，
> 但**闭包语义、参数转换、调用栈记录**三方面与 C 有偏差（TODO.txt MEM-2）。
> 现状基线：lab/learning `52d89fc`

---

## 一、现状：递归已能跑，但语义有三处缺口

当前调用路径（`ExeFuncCall`）：

```python
outer_scope = g_scope
g_scope = Scope(func.closure_scope)      # 新建作用域，parent = 定义时捕获的作用域
for i, pname in enumerate(func.param_names):
    g_scope.declare(pname, args[i], func.param_types[i])   # 直接存值
try:
    result = execute(func.body)
except ReturnException as e:
    return e.value
finally:
    g_scope = outer_scope
```

**已验证可用**：递归阶乘 `fact(5)=120`、互递归 `is_even(10)=1`——每次调用新建 Scope、finally 恢复，局部变量天然隔离。

**但有三处与 C 的偏差**：

| # | 偏差 | 现状行为 | C 语义 |
|---|---|---|---|
| 1 | **闭包作用域** | `closure_scope` = 函数**定义时**捕获的 g_scope | 顶层函数应绑定**全局**作用域；块内/嵌套函数（GNU 扩展）绑定定义处块 |
| 2 | **参数类型转换** | 实参原样 `declare`（除 struct 深拷贝） | C 调用约定：char/short→int 提升、double 传参、指针/数组退化（这部分归 TYPE-2，MEM-2 只搭框架） |
| 3 | **无调用栈记录** | 仅 g_scope 切换，无调用栈元数据 | 应有调用栈（错误回溯、QOL-1、setjmp/longjmp CTRL-2 的基础） |

## 二、设计：调用栈 + 栈帧

### 2.1 数据结构

```python
class StackFrame:
    """一次函数调用的完整上下文。"""
    __slots__ = ("func_name", "scope", "caller_scope", "ret_type")

    def __init__(self, func_name, scope, caller_scope, ret_type=None):
        self.func_name = func_name      # 便于错误回溯
        self.scope = scope              # 本帧作用域（参数 + 局部变量）
        self.caller_scope = caller_scope  # 调用者作用域（返回时恢复）
        self.ret_type = ret_type        # 返回类型（可选，供类型检查）

g_call_stack = []   # list[StackFrame]：当前调用链（栈顶 = 活动帧）
```

### 2.2 调用协议（ExeFuncCall 改造）

```
调用一个用户函数：
1. frame = StackFrame(func_name, Scope(global), caller_scope=g_scope)
   —— parent 用 **全局作用域**（C 顶层函数语义），不再用 closure_scope
2. 参数按 C 规则转换后 declare 到 frame.scope
   （MEM-2 只做：struct/union 深拷贝；其余标量原样——完整转换归 TYPE-2）
3. g_call_stack.append(frame); g_scope = frame.scope
4. try: execute(func.body)
   except ReturnException as e: return e.value
   finally: g_scope = frame.caller_scope; g_call_stack.pop()
```

关键变化：**`Scope(func.closure_scope)` → `Scope(g_global_scope)`**。
- 顶层函数：closure_scope 本来就等于全局 → 行为不变（零回归）
- 语义修正：函数体访问外部变量一律走**全局**（C 语义），不再受"定义点作用域"干扰
- 嵌套函数（GNU 扩展 `__attribute__((...))` 块内定义）：当前 parser 支持但极少用，MEM-2 以全局为准（与 C 顶层函数一致），如需词法闭包另开 TYPE-4

### 2.3 全局变量读写（配套修正）

`Scope.set` 目前沿父链找到**第一个**同名 Symbol 写值。函数内 `g_scope = Scope(global)` 后：
- 局部变量（参数/块内声明）在 frame.scope 首层 → 正常
- 函数内写全局变量 `g = 5`：frame.scope 无 `g` → 沿父链找到全局 Symbol → 写入 ✅ 已正确
- 函数内声明同名 `int g;`（遮蔽）：frame.scope 首层 declare → 本帧独立，不影响全局 ✅ 已正确

**结论**：Scope 链已支持"局部遮蔽 + 全局可写"，只需把 parent 从 closure_scope 换成 g_global_scope 即符合 C。

### 2.4 尾递归（可选优化）

TODO 列为可选。深度递归（如 `fact(10000)`）会耗尽 Python 递归栈。MEM-2 不做尾递归优化（TRPO），文档记录：
- 深递归上限 = Python sys.getrecursionlimit（约 1000）
- 需要时可在 CallStack 上做尾调用复用（栈顶帧直接替换，不新增帧）

## 三、对现有功能的影响

| 现有能力 | 变化 |
|---|---|
| 递归（fact/mutual） | 不变（行为等价，parent 语义修正） |
| 全局变量读写（T4） | 不变（g_global_scope 与 closure_scope 对顶层函数相同） |
| struct 值传递（M5） | 不变（参数深拷贝保留） |
| __builtin_va_list 帧栈 | 不变（独立于调用栈，push/pop 时序在 frame 切换内） |
| 函数指针 / 惰性解析 | 不变（g_functions 查找与作用域无关） |
| 错误回溯（QOL-1） | 受益：g_call_stack 提供调用链（后续接入） |
